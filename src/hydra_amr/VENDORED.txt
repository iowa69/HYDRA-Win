Vendored copy of hydra_amr
==========================

Source:   https://github.com/iowa69/hydra

Everything in this directory is upstream code. The only edits are marked
"HYDRA-WIN PATCH" and are listed here, so a re-vendor is: copy the new
upstream src/hydra_amr over this directory and re-apply these hunks.

1. utils.py   - adds the module attribute RUN_HOOK (default None) and, inside
                run(), lets that hook rewrite the command line and add
                subprocess.run() keyword arguments. Hydra-win installs a hook
                (hydra_win/winsafe.py) that, on every external command:
                  * hides the console window (CREATE_NO_WINDOW) and detaches stdin;
                  * runs the tool from a fixed, space-free ASCII working directory
                    and hands BLAST+ relative paths for -db/-query/-out/-in,
                    because BLAST+ mis-parses spaces in -db, cannot open
                    non-ASCII paths on Windows, and makeblastdb fails on a
                    working directory containing a space;
                  * makes makeblastdb build version-4 databases (no LMDB index:
                    on Windows each LMDB file is allocated at its full map size).
                With RUN_HOOK left at None behaviour is identical to upstream.

2. db/fetch.py - _get_via_tool() (the curl/wget fallback used for VFDB) runs
                with stdin detached and, on Windows, CREATE_NO_WINDOW, so no
                console window flashes during a database download.

3. Mutation detail (what exactly mutated), additive; proposed to upstream as a
   pull request with the identical engine code, so this entry disappears at the
   next re-vendor once it is merged:
     engines/lesions.py  NEW. For every call already made, reads the assembly at
                         the place the alignment points to and names the change:
                         codon/base read from the contig (alignment walked, strand
                         and indels handled), reference base from the DNA
                         catalogue's reference sequence or a parsimony inference
                         labelled as such, AMRFinderPlus/HGVS/Kleborate names,
                         disruption lesion (stop, frameshift, interruption, start
                         loss, contig end), resistance in words.
     records.py          MutationDetail record; Hit gains `mutation` (the detail)
                         and `evidence` (alignment, never written out); as_row()
                         and HIT_COLUMNS gain the detail columns at the end.
     engines/protein.py  the three mutation callers attach `evidence` to the Hit
                         they already build (POINTX, POINTN, DISRUPTX); the DNA
                         caller keeps the reference sequences it already reads.
     pipeline.py         one call to lesions.describe_mutations() per assembly
                         after screening.
     engines/reads.py    read-derived site and variant calls get the same detail
                         (not used by HYDRA-Win, kept identical to upstream).
     report/             hydra.mutations table, detail in the HTML report (not
                         used by HYDRA-Win, kept identical to upstream).
   Which mutations are called is unchanged: tools/compare_upstream.py matches
   upstream at the commit above on every existing field.

Nothing else is changed. Upstream modules Hydra-win does not import
(cli.py, report/, engines/reads.py's read-mapping code paths) are kept so the
copy stays diffable against upstream; the read engine imports pysam lazily and
is never called on the assembly path.
