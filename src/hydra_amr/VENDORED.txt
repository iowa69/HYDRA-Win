Vendored copy of hydra_amr
==========================

Source:   https://github.com/iowa69/hydra
Commit:   c020035fbd2c3850bb0684f8ab33c9bbaf52c4f5  (branch typing-integration,
          2026-11-17, hydra_amr 1.4.0). That branch is open as pull request #3
          and merges #2 (mutation-detail), so it contains both.
Path:     src/hydra_amr  (copied verbatim, plus the upstream LICENSE file)
Licence:  MIT (see LICENSE in this directory)

Everything in this directory is upstream code. The only edits are marked
"HYDRA-WIN PATCH" and are listed here, so a re-vendor is: copy the new
upstream src/hydra_amr over this directory and re-apply these hunks.

1. utils.py   - adds the module attribute RUN_HOOK (default None) and, inside
                run(), lets that hook rewrite the command line and add
                subprocess.run() keyword arguments. Hydra-win installs a hook
                (hydra_win/winsafe.py) that, on every external command:
                  * hides the console window (CREATE_NO_WINDOW) and detaches stdin;
                  * runs the tool from a fixed, space-free ASCII working directory
                    and hands BLAST+ relative paths for -db/-query/-out/-in,
                    because BLAST+ mis-parses spaces in -db, cannot open
                    non-ASCII paths on Windows, and makeblastdb fails on a
                    working directory containing a space;
                  * makes makeblastdb build version-4 databases (no LMDB index:
                    on Windows each LMDB file is allocated at its full map size).
                With RUN_HOOK left at None behaviour is identical to upstream.

2. db/fetch.py - _get_via_tool() (the curl/wget fallback used for VFDB) runs
                with stdin detached and, on Windows, CREATE_NO_WINDOW, so no
                console window flashes during a database download.

Nothing else is changed, and there is no third entry any more: the mutation
detail that v0.3.0 carried as a local patch is upstream code on the vendored
branch (pull request #2), with the identical engine, and
tools/compare_upstream.py still checks the workbooks against it.

What the vendored branch adds beyond main (pull request #3):

  typing/organisms/   eight organism typing modules - S. aureus, S. pyogenes,
                      S. agalactiae, S. pneumoniae, H. influenzae,
                      N. meningitidis, Salmonella, E. coli/Shigella - each with
                      its own fetch() that installs its data under
                      <db>/organisms/<key>/, its tests and its documented
                      method and bibliography (upstream docs/typing/).

  typing/organisms/registry.py
                      selects the modules for a sample from the species call,
                      or from the MLST scheme when there is no species call;
                      gives every scheme a readable heading; records in
                      DB_LAYOUT which files on disk belong to which declared
                      database, which is what lets this build ship part of a
                      module's data and download the rest (see
                      hydra_win/databases.py, ORGANISM_ROUTES).

  records.py          TypingResult gains title (readable heading), organism
                      (which module made the call) and the evidence() /
                      as_detail_row() helpers. Additive: no existing field
                      changed.

  pipeline.py         runs the organism modules for every assembly, gated by
                      the existing typing option, and records against the
                      sample why a module was skipped.

  engines/blast.py    safe_threads(): a translated search runs single-threaded,
                      because BLAST+ 2.16.0 segfaults on a no-hit
                      blastx/tblastn when -max_target_seqs is combined with
                      -num_threads > 1. That is the same BLAST+ 2.16.0 this zip
                      ships, so the fix matters here as much as on Linux.

  report/, db/        the typing evidence reaches the TSV and HTML output, and
                      hydra db download typing-<key> installs a module's data.
                      HYDRA-Win does not import report/, and installs the
                      organism data through hydra_win/databases.py instead, but
                      both are kept so the copy stays diffable against upstream.

What this re-vendor brought in (the five decisions of v0.5.0):

  engines/lesions.py  disclose_contig_end(): a gene cut by a contig end is
  records.py          still reported, and the row now says so in its own
  typing/lineage.py   columns - element_subtype DISRUPTION_AT_CONTIG_END and
                      resolution CONTIG_END, both named in records.py - with the
                      note leading on it and the resistance field no longer
                      asserting a loss of function that was never established.
                      resistance_score() ignores such a row, so an unassessable
                      lesion is not counted as resistance that is present.
                      hydra_win/excel.py styles these rows with
                      NOT_CONFIRMED_FONT wherever a reader meets a single cell.

  engines/protein.py  pmrB (K. pneumoniae complex, colistin) and acrR
                      (Escherichia, multidrug) added to LOSS_OF_FUNCTION, which
                      is what makes Hydra report HS11286's pmrB_A21DfsTer16
                      (Kleborate's pmrB:p.Gly20fs) and EC958's acrR_F180LfsTer3
                      (AMRFinderPlus's own symbol). tools/ci.py asserts both.

  db/fetch.py         verify_pubmlst_is_pre_2025(), pubmlst_access_note() and
  db/registry.py      write_pubmlst_provenance(), plus PUBMLST_TERMS quoted once.
                      This is what lets the PubMLST snapshot be bundled: the
                      terms permit redistributing data submitted on or before
                      2024-12-31, an anonymous client can see nothing else, and
                      the build now asks the server to confirm it rather than
                      taking it on trust. tools/ci.py check_pubmlst_bundle()
                      fails the build if the confirmation is missing.

  typing/organisms/   the meningococcal and H. influenzae PubMLST data is
    nmeningitidis.py  recorded as redistributable, so hydra_win/databases.py
    hinfluenzae.py    ships it; a disrupted capsule is called
    _hinf_nmen_common "B (capsule gene disrupted)" rather than a bare NG, and
    registry.py       the same wording is shared with the H. influenzae module;
                      rank_serogroups() separates W from Y on the sequence
                      instead of on the serogroup's name; and
                      DB_SHARED_WITH_PUBMLST names the per-module allele sets
                      the bundled pubmlst database replaces, which is what
                      hydra_win/databases.py shared_pubmlst_copies() reads so
                      the zip carries one copy and not five.

Upstream modules HYDRA-Win does not import (cli.py, report/, engines/reads.py's
read-mapping code paths) are kept for the same reason; the read engine imports
pysam lazily and is never called on the assembly path.
